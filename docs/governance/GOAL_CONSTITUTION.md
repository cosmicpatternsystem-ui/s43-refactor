# Goal Constitution

This document is the durable goal constitution of the project.

It defines the top-level intent that must survive tool changes, personnel changes, AI model changes, vendor changes, hardware changes, and long-term project evolution.

## Mission

Build a globally credible, commercially serious, durable, and extensible financial intelligence and governance platform that can operate as a foundation for future systems and domain-specific adaptations.

## 50-Year Direction

The project must be designed for long-term survival rather than short-term convenience.

Required properties:

- durable file formats
- repository-first knowledge
- explicit contracts
- automated validation
- minimal hidden state
- migration-friendly schemas
- replaceable tooling
- vendor-neutral operations where practical
- compatibility awareness
- reproducible governance
- low-dependency critical path

## Commercial Direction

The project must be capable of supporting both private and enterprise-grade commercial use.

Commercial design must prioritize:

- real customer pain
- decision quality
- trust
- reliability
- privacy
- auditability
- operational clarity
- extensible deployment models
- premium positioning
- defensible uniqueness

## Global Reference Direction

The project should aim to become a reference-grade system, not merely an internal tool.

Reference-grade means:

- precise terminology
- reproducible methodology
- strong documentation
- verifiable behavior
- portable contracts
- operational discipline
- modular adaptation path
- measurable quality

## Autonomy Direction

The project should reduce dependence on continuous human memory and manual coordination.

Autonomy means:

- repository-contained instructions
- automated checks
- roadmap synchronization
- drift detection
- CI enforcement
- agent onboarding
- repeatable workflows
- machine-readable contracts

## Adaptability Direction

The project must act as a reusable foundation for other projects.

The architecture must distinguish:

- immutable principles
- configurable policy
- domain-specific extensions
- replaceable implementation details

## Non-Negotiable Invariants

The project must not depend on chat memory as a source of truth.

The repository is the authoritative system of record.

Material changes must be traceable.

Governance must be testable.

Roadmap state must be machine-readable.

Documentation and contracts must not knowingly contradict each other.

Critical workflows must fail closed when governance evidence is missing.

The project must prefer boring durable formats over fragile cleverness.

## Success Criteria

The project becomes stronger when a new operator can enter without prior context, read the repository, understand the direction, make a safe change, pass validation, and continue the professional path without relying on private memory.
